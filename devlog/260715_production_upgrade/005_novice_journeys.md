# 005 — 디자인 알못 사용자 여정과 정보구조

## 문제

현재 사이트는 이름을 아는 사람이 ISM/패턴을 찾아보는 데는 좋지만, 초심자의 실제 질문은
"무슨 스타일을 써야 하지?", "이 효과 이름이 뭐지?", "그래서 코드에 뭘 붙이지?"다.
페이지를 늘리는 대신 기존 Isms/Effects/FAQ 축 안에서 이 세 질문을 연결한다.

## 핵심 여정

| 시작 질문 | 진입점 | 결과 | 다음 행동 |
|-----------|--------|------|-----------|
| 어떤 스타일이 맞나 | index 상단 Style Finder | 3개 추천 + 이유 | ISM 모달 열기 |
| 이 화면 효과 이름이 뭔가 | Effects family/device/search | 전용 데모/설명 | 코드 복사 |
| 이 스타일을 구현하고 싶다 | ISM 모달 development guide | palette/type/spacing/motion | CSS/Tailwind/JSON 복사 |
| AI에게 시키고 싶다 | ISM 모달 Prompt Pack | 제약이 포함된 프롬프트 | 복사 후 도구에 전달 |
| 결과가 어색하다 | dos/donts + FAQ | 실패 원인/QA 순서 | before/after 기준으로 수정 |

## UX 원칙

- 첫 화면의 기본 행동은 검색/탐색. Finder는 보조 진입점이며 거대한 marketing hero가 아니다.
- 용어를 모르는 사용자는 프로젝트 종류/분위기/밝기만 답한다. 세부 조절은 결과 뒤로 숨긴다.
- 추천은 점수만 노출하지 않고 "왜 추천했는지" 키워드 2–3개를 보여준다.
- `ai-slop`은 교육용 anti-pattern이며 기본 추천 후보에서 제외한다.
- 모달 하나에서 역사→이미지→구현 가이드→코드→프롬프트로 이어지되 처음부터 모든
  섹션을 펼쳐 인지 부하를 만들지 않는다.

## IA 결정

- 신규 공개 reference/backlog 페이지 없음.
- Finder는 `index.html` 안의 접이식 작업 영역.
- 코드 내보내기/Prompt Pack은 기존 ISM 모달의 탭/섹션.
- 비주얼 이펙트는 Effects의 새 `family` 축으로 흡수한다.

## 성공 신호

- 첫 방문자가 30초 안에 사이트 목적, 스타일 추천 진입점, 구현 가이드 위치를 찾는다.
- Finder 결과에서 1클릭으로 추천 ISM 모달을 연다.
- 코드/프롬프트 복사 성공이 live region으로 확인되며 실패 시 복구 경로가 있다.
